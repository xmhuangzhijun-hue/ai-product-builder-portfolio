FDE 能力对照 · CAPABILITIES × EVIDENCE

每一项能力，都指到一份证据。

这七项与我简历上的「FDE 能力对照」同名同序——简历上看到哪一条，在这里就能点开对应的案例章节、源码或测试摘要。FDE 的工作大致是两件事：在现场先修出一条能跑的「碎石路」解决眼前问题，再把其中反复出现的部分沉淀成别人也能用的「高速公路」。下面按这个顺序排列——从看懂现场、修通路，到把路留给后来的人。

1 · 技术与业务双向翻译

长期在一线直接对接运营、代理与决策人。系统拿不到数据时不等需求文档，自己把业务痛点翻译成技术需求；也能把技术约束讲成业务后果，让非技术方理解取舍。

看板案例：动手之前的数据需求清单 →

2 · 系统集成与数据接入

在没有开放 API 的条件下，从已授权网页报表识别结构化数据请求并设计采集与导入路径；打通 BI、媒体官方 API、飞书 / 钉钉与自建数据库。

技术与实现范围

Python、pandas、Excel；Chrome CDP / 结构化响应；OAuth / OpenAPI 独立接入；飞书与钉钉自定义机器人、Webhook 推送。

看板案例：没有现成接口怎么取数 →

3 · 数据工程与口径治理

ETL / 数据建模 / 数据质量全链路：采集 → 清洗 → 入库 → 指标口径统一；针对重复分页、BI 补数、时间范围不一致等故障设计校验规则与停止条件，避免「抓到了但抓错了」。

技术与实现范围

字段归一化、重复检测、时间对齐、批次指纹、缺失值语义；SQLite / WAL、行哈希与批次记录。

看板案例：降低「抓错了」的风险 →脱敏测试摘要 →

4 · 原型到生产与运行保障

先用固定数据原型把方案做成可评审的形态，再上生产：服务端数据权限、多租户角色、定时任务、发布流程；并配套数据稳定性门、异常自动预警、备份恢复与真实回滚演练。

技术与实现范围

React、TypeScript、Tailwind（原型）；Streamlit / AgGrid、FastAPI；Linux / systemd timer、Nginx / HTTPS；Argon2id、Session、角色与数据作用域。

可操作的投放中台原型 →看板案例：可验证结果与运行 →

5 · 文档与可复用资产

把一次性交付沉淀成可复用资产：运营知识库、ROI 异常归因框架、回传监控指标体系、指标口径对照、部署与运维说明，供后续项目和其他同事直接复用，而不是留在某个人脑子里。

工作经历与职责范围 →数据准确性实践笔记 →

6 · 交付与交接

离职时交付受控源码包、Git 历史 bundle、安装与校验脚本、部署 / 回滚 / 备份恢复说明、生产秘密移交清单，并完成代码仓库所有权转移——系统在我离开后仍可运行与恢复。

看板案例：我离开时把系统交干净了 →

7 · AI 与 Agent 落地

用编码 Agent 完成从需求定义到生产上线的完整交付；能定位开源 Agent 项目的真实缺陷，并提交被上游采纳的修复。

技术与实现范围

Claude Code / Codex 全流程协作；Hermes 二次开发、重试与后备路径、同会话异步预处理、自动记忆写入边界、事件与回执。

公开修复与上游合入记录 →Agent 外壳与连接实验 →
这些能力都长在真实业务里，不是课程清单。每一项都注明了当前阶段与边界：已上生产的、只到原型的、仍是实验的，分别标注，不混为一谈。
